Следующая строка, когда продолжение однозначно. Подсказка появляется после Enter или при наборе её начала. Работает по правилам и без gopls.

Запуск и отладка

Конфигурация Go создаётся значком запуска на полях редактора или вручную. Для программ проекта конфигурации создаются сами.

Конфигурации GoLand в проекте (Go Build и Go Test в .idea/workspace.xml или в общих файлах .run) открываются как конфигурации Go и запускаются плагином: пакет, файл или каталог, рабочий каталог, аргументы программы и команды go, переменные окружения, шаблон тестов. Сохраняются они в формате GoLand, так что общий файл по-прежнему открывается в GoLand. Новые такие конфигурации не создаются: в списке Add New Configuration только Go.

Что запускается

KindНазначение
go runПрограмма: каталог пакета или отдельный файл.
go testТесты, бенчмарки или фаззинг пакета.
BinaryУже собранный исполняемый файл.
Core dumpДамп памяти вместе с исполняемым файлом, из которого он получен. Только отладка.
Remote dlv dapОтладка через dlv dap, запущенный на другой машине: подключение к процессу или запуск файла там. Поля dlv dap at, Process id there и Path substitutions.
go run / go test на SSH-хостеПоле SSH host (user@host, ssh://user@host:port или хост из ~/.ssh/config, вход по ключу): только Debug. Программа и delve собираются здесь под платформу хоста и копируются туда (Directory there, по умолчанию ~/.cache/<имя проекта>; каталог, в который могут писать другие пользователи, не принимается). delve слушает там unix-сокет во временном каталоге, доступном только вам, и подключается через ssh -W: TCP-порта нет ни там, ни здесь. Files to copy — таблица: кнопка + добавляет файлы и каталоги проекта (путь относительно каталога пакета), вторая колонка — куда класть там; они едут в рабочий каталог программы с правами 600 и повторно не пересылаются, пока не изменились. Там они лежат по тому же относительному пути (certs/ca.pem), или по относительному пути из второй колонки. Файлы вне проекта и пути вне рабочего каталога не принимаются: конфигурация запуска может прийти вместе с чужим проектом. У go test каталог testdata пакета копируется сам (флажок).

Инспекции в CI

Те же проверки Go и go.mod, что в редакторе в режиме Built-in, прогоняются по всему проекту из меню Go и пишут отчёт SARIF 2.1.0: его читают GitHub code scanning, GitLab и другие. gopls для этого не нужен, и режим Language features переключать не надо: на время прогона включаются встроенные проверки.

ДействиеЧто делает
Go, Inspect Project новоеВсе проверки Go и go.mod, включённые в профиле, по проекту. Результаты в окне Inspection Results: дерево по проверкам и файлам, переход к месту, исправления по одной находке и сразу для всех. В дереве проекта на каталоге — только по нему.
Go, Export Inspections to SARIF… новоеТот же набор в фоне, с прогрессом и отменой; отчёт пишется в файл из диалога сохранения, по умолчанию go-inspect.sarif в корне проекта. По окончании — уведомление «92 findings written to go-inspect.sarif» с кнопками Open File и Show in Explorer (Reveal in Finder на macOS).
Go, Reanalyse Project Problems новоеПолный проход фонового анализа сейчас (прогресс «Analysing Go project» в строке состояния) и вкладка Problems, Project Errors. Доступно, когда на странице Settings, Go, Linters включено «Analyse the whole project in the background» и Power Save Mode выключен.

В CI то же самое запускается без окна. go-inspect — режим запуска самой IDE, а не отдельная программа: команду получает лаунчер IDE, в которую установлен плагин (idea64.exe на Windows, idea.sh на Linux и macOS; подойдут и pycharm64.exe, webstorm.sh и другие). IDE с той же конфигурацией в это время не должна быть открыта; на машине разработчика проще задать отдельный каталог конфигурации. Подробности, код выхода на Windows и пример задания GitHub Actions — docs/CI.md.

> idea64.exe go-inspect . report.sarif --min-severity warning go-inspect: 48 inspections, 27 files, 65 findings (4 error, 61 warning, 0 note), 0 inspection failures, 8412 ms -> report.sarif $ idea.sh go-inspect . report.sarif; echo $? go-inspect: 48 inspections, 27 files, 92 findings (4 error, 61 warning, 27 note), 0 inspection failures, 8530 ms -> report.sarif 1
АргументЧто задаёт
<projectDir> <out.sarif>Каталог проекта (с go.mod или go.work) и файл отчёта.
--inspections A,BТолько эти инспекции по коротким именам, даже если профиль их выключает. Без него — все включённые в профиле проекта.
--min-severityweak (всё, по умолчанию), warning или error: что слабее, в отчёт не попадает.

Пропускаются vendor, testdata, каталоги с . и _ в начале, сгенерированные файлы (// Code generated … DO NOT EDIT.) и файлы, которые условия сборки исключают. Нужен go в PATH: без него не найти стандартную библиотеку.
