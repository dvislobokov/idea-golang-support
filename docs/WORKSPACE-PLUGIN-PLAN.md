# План: плагин «Workspaces» для IDE на платформе IntelliJ (отдельный проект)

Составлен 2026-10-02. Это план **нового, самостоятельного плагина**, не связанного с Go-плагином: он зависит только от
`com.intellij.modules.platform` и должен работать в IntelliJ IDEA, PyCharm, WebStorm, Rider, Android Studio и форках.
Файл лежит здесь временно, до создания репозитория плагина (`../idea-workspaces`).

## 1. Зачем

Пользователям нужен аналог multi-root workspace VS Code и workspace Eclipse: несколько репозиториев в одном окне, с общим
поиском, навигацией, терминалом и запуском. У JetBrains есть свой плагин
[Multi-Project Workspace](https://plugins.jetbrains.com/plugin/24765-multi-project-workspace) (231 тыс. загрузок,
оценка 4.06 при 27 голосах, статус preview, сборка еженедельно под точный билд IDEA). Его отзывы (снято 2026-10-02) — это
и есть список того, что надо сделать лучше:

| Жалоба | Сколько раз | Почему у JetBrains так |
|---|---|---|
| Только IntelliJ IDEA; просят PyCharm, WebStorm, Android Studio (в т. ч. чтобы AI-ассистент видел бэкенд и фронтенд разом) | 4 | внутренние API сборочных систем IDEA |
| Ломается после обновления IDE (2025.1: Gradle-jar не подтягиваются; 2026.1: не работают добавление и удаление проекта) | 3 | привязка к точному билду, внутренние API |
| Иерархии и поиск не видят весь workspace (иерархия интерфейса базового проекта показывает 1–2 проекта из 20) | 1, критичная | схема «отдельные библиотеки на проект» |
| Добавление проектов по одному; нужен мультивыбор и обнаружение репозиториев под родительской папкой | 1 | — |
| Многомодульный Maven не добавляется («cannot be added to workspace» без причины); Unload для Maven не работает | 2 | — |
| Имя проекта приклеено к имени файла во вкладках; нельзя скрыть путь; git-виджет мешает ветки всех репозиториев | 3 | — |
| Один workspace на окно; хочется вкладки проектов, как на macOS | 2 | нет системных вкладок окон вне macOS |

Сильная сторона их плагина, которую стоит сохранить: «отдельные External Libraries на проект» и перенос run-конфигураций.

## 2. Что такое workspace в этом плагине

- **Файл workspace** `*.ijworkspace` (JSON или TOML) рядом с кодом, с относительными путями — можно коммитить и делиться в команде,
  как `.code-workspace`:
  ```json
  { "name": "shop", "folders": [ { "path": "../shop-api", "name": "api" }, { "path": "../shop-web" } ], "settings": { "activeFolder": "api" } }
  ```
- Открытие файла workspace = открытие проекта платформы, чей `.idea` лежит рядом с файлом (каталог `<name>.ijworkspace.idea/`
  или `.idea` в папке workspace). Каждая папка workspace становится **модулем с content root** через `WorkspaceModel`
  (`MutableEntityStorage`, `ModuleEntity`, `ContentRootEntity`); сами папки не трогаются: их `.idea` остаются как есть.
- Два режима индексации (выбор при создании, можно сменить): **общий индекс** (все папки — модули одного проекта: Find Usages,
  иерархии, Search Everywhere видят всё; зависимости общие) и **раздельные зависимости** (на папку — свой набор библиотек через
  `LibraryEntity` в scope модуля; поиск по проекту остаётся общим). Это главный компромисс, см. §6.

## 3. Функции MVP (по убыванию ценности)

1. **Создать / открыть workspace**: действие File | New Workspace…, Open открывает `*.ijworkspace`; Welcome screen показывает их в Recent с иконкой.
2. **Добавить папки массово**: диалог с деревом от родительской папки, обнаружение репозиториев по маркерам (`.git`, `go.mod`, `package.json`,
   `pom.xml`, `build.gradle(.kts)`, `pyproject.toml`, `Cargo.toml`, `*.sln`/`*.csproj`), чекбоксы, drag-and-drop папок в Project view.
3. **Удалить папку** из workspace (без удаления с диска), **временно выгрузить** (unload модуля платформы).
4. **Активная папка** как понятие: подсветка в Project view, виджет статус-бара со списком и быстрым переключением (Ctrl+Alt+`);
   контекст активной папки получают терминал (cwd), run-конфигурации по умолчанию, git-виджет (фильтр веток — через `GitRepositoryManager`
   и свой виджет вместо платформенного, если фильтровать его нельзя), «Find in Files» scope «Active folder».
5. **Чистые вкладки редактора**: имя файла без приставки проекта; папка — цветной маркер вкладки (`EditorTabColorProvider`) и группа в
   Recent Files (`RecentLocationsManager` не трогаем, своя Switcher-подобная popup).
6. **Несколько workspace**: переключатель workspace в том же окне (закрыть проект, открыть другой в этом кадре:
   `ProjectUtil.openOrImport` с `OpenProjectTask(forceOpenInNewFrame = false)`); список недавних workspace отдельно от проектов.
7. **Импорт из плагина JetBrains**: прочитать его workspace и создать наш файл.
8. **Совместимость с инструментами сборки**: плагин ничего не импортирует сам; если в IDE есть Gradle/Maven/npm-плагины, они видят
   свои файлы внутри content roots и предлагают связать проект (Gradle: `linkAndRefreshGradleProject` по запросу пользователя из нашего диалога —
   это внутренний API, держать за `<depends optional>`).

Не в MVP: вкладки окон, как на macOS (см. анализ: эмуляция через скрытые кадры хрупка), per-folder настройки IDE (платформа хранит
настройки на проект; эмулировать только для ограниченного набора: code style через `CodeStyleSettingsManager` per module scope — отдельное решение).

## 4. Архитектура

| Компонент | Что | API |
|---|---|---|
| `WorkspaceFile` | чтение/запись `*.ijworkspace`, относительные пути, миграции версий | чистый Kotlin, тесты без платформы |
| `WorkspaceOpenProcessor` | открытие файла workspace как проекта | `com.intellij.projectOpenProcessor` |
| `WorkspaceSync` | файл ↔ модули/content roots; наблюдение за файлом (VFS) и за ручными изменениями структуры | `WorkspaceModel`, `WorkspaceModelChangeListener` |
| `FolderDiscovery` | поиск репозиториев под папкой по маркерам | `VfsUtil`, фоновая задача |
| `ActiveFolderService` | активная папка, слушатели | project service, `MessageBus` |
| UI | действия, диалог добавления, виджет статус-бара, маркеры вкладок, Project view decorator | `StatusBarWidgetFactory`, `EditorTabColorProvider`, `ProjectViewNodeDecorator` |
| Интеграции | git-фильтр, терминал cwd, scope поиска | `<depends optional>` на Git4Idea / Terminal |

Принципы: только публичные API; `sinceBuild` диапазоном (например 2024.2–2026.x), а не точный билд; все расширения
`DumbAware`; никаких правок в `.idea` папок-участников; удаление папки из workspace никогда не трогает диск.

## 6. Риски и решения

- **Общий индекс против раздельных зависимостей.** Один индекс даёт то, чего не хватает в плагине JetBrains (иерархии по всему
  workspace), но смешивает зависимости разных проектов одного стека (две версии одной библиотеки). Решение: общий индекс по умолчанию,
  раздельные зависимости как режим W6; в обоих режимах поиск по исходникам общий.
- **Сборочные системы.** Их импортёры — внутренние API и разные в каждой IDE; плагин не импортирует сам, а только показывает папку как
  content root и предлагает пользователю связать проект штатным способом IDE. Это и есть причина, по которой он переживает обновления.
- **Git-виджет платформы** нельзя отфильтровать публично — свой виджет с ветками активной папки, платформенный можно скрыть настройкой.
- **Переключение workspace** всегда с перезагрузкой проекта (секунды): так устроена платформа, честно написать в описании.

## 7. Чем лучше плагина JetBrains (обещание в описании на Marketplace)

Все IDE платформы; не ломается на обновлениях (публичные API, диапазон билдов); добавление десятков репозиториев за раз;
файл workspace в репозитории команды; активная папка как контекст для git, терминала, запуска и поиска; чистые вкладки;
несколько workspace с быстрым переключением; общий поиск и иерархии по всему workspace.
