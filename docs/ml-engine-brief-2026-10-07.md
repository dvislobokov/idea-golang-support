# Бриф для агента движка (`../idea-ml-completion`), второй живой прогон go-nn-31m-e2, 2026-10-07

Контекст: Go-плагин 0.2.203–0.2.205 работает на движке ac9b3fd (`healMode = WORD_EOL`, `trimClosersAfterCaret`, порог 0.7).
Лечение от начала слова и обрезка закрывателей вживую подтверждены (`return l` → `en(o.items)` 0.72, показано). Ниже то, что
всплыло дальше, по убыванию важности. Все цифры — на файле `playground/store/order.go` Go-плагина, SPM, настройки по умолчанию.

## 1. Набранный остаток в другом регистре: `fmt.err` → ничего

Ограничение по набранному остатку побайтное и регистрозависимое. После `fmt.` модель уверена в `Errorf` (p = 1.00), но стоит
набрать `e`, как разрешёнными остаются только токены с маленькой буквы, и генерация сворачивает на `errors.New`:

| набрано | ответ | confProd |
|---|---|---|
| `fmt.` | `Errorf("store: no items")` | 0.016 |
| `fmt.e` | `rrors.New("store: no items")` | 0.005 |
| `fmt.err` | `ors.New("store: no items")` | 0.014 |

Нужно: опция `Options.healIgnoreCase` (по умолчанию включена), при которой `VocabPrefixIndex.allowed(rem)` и `consume` сравнивают
байты без учёта ASCII-регистра, а в `Result` появляется поле `typedByModel: ByteArray` — как модель написала набранную часть
(`Err` для `err`). Плагин покажет серый текст после каретки и при принятии заменит набранное на `typedByModel`. Тест в
`NnCompletionTest`: `fmt.err` даёт `orf(...)` с `typedByModel = "Err"`; `NnHealParityTest` не ломать (опция выключена в фикстуре).

## 2. Уверенность по байтам, а не по токенам: `("` против `(` + `"`

На `return fmt.Errorf` в функции, возвращающей `error`, вероятности по токенам: `Errorf` 1.00, `("` 0.73, конец строки 0.89.
Токен `("` есть в словаре и как целый, и как `(` + `"`; масса делится между двумя написаниями одного и того же продолжения, и
`confProd` занижается без реальной неуверенности. Там, где у следующего шага несколько токенов с общим началом, уверенность шага
стоит считать как сумму их вероятностей (или хотя бы вероятность по первому байту), а не вероятность одного выбранного токена.
Проверить на тестовом фолде, как это меняет калибровку порога (0.7 сейчас), и дать новую рекомендацию.

## 3. Строковые литералы в `confProd`

Любая строка с литералом получает 0.001–0.05: каждое слово сообщения маловероятно само по себе, а произведение по строке
схлопывается (`fmt.` → `Errorf("store: no items")` 0.016; каретка внутри кавычек → `"store: no items"` 0.015). Плагин с 0.2.204
считает уверенность только по коду (токены вне `"…"`, `` `…` ``, `//`, без открывающей и закрывающей кавычки — они часть догадки)
и показывает строку с угаданным текстом; это `GoNnInline.codeConfidence` в `GoNnInlineCompletionProvider.kt`. Лучше перенести это в
движок как `Result.confCode` рядом с `confProd` (и использовать его в `show` по опции), чтобы C#-плагин не повторял логику. Там
же: при каретке внутри литерала остановка генерации на закрывающей кавычке, а не на конце строки, — сейчас модель дописывает
всё до `\n`.

## 3а. `trimClosersAfterCaret` режет мало

На `func (o *Order) Validate() (int⟨⟩) {` модель ответила `, error) {` (0.86, показано), после Tab вышло `(int, error) {) {`:
хвост `) {` уже есть после каретки, но `{` не закрыватель, и движок его оставил. Правило должно быть общим: отбрасывать самый
длинный хвост подсказки, с которого начинается остаток строки после каретки (с пробелами), а не только хвост из закрывателей.
Плагин с 0.2.206 делает это сам (`GoNnInline.trimOverlap`), лучше перенести в движок.

## 4. Модель: `Errorf` после `fmt.` в функции с результатом `error`

В файле без `errors` в импортах и без переменной-ошибки выше (тест `GoNnModelTest.guessesTheStringOfErrorf`) `Errorf` после
`fmt.` получает лишь ~0.75 (конкурирует `Sprintf`), с `errors.New` выше по файлу — 1.00. Тип результата функции модель не видит.
Идея для следующего обучения или для промпта: подсказывать модели сигнатуру текущей функции (например, строкой-комментарием
перед префиксом или отдельным спецтокеном), чтобы `return` в `func … error` тянул к `fmt.Errorf` / `errors.New` без контекста.
Это проверка на данных, не обязательство.

После правок — `tools/ml/sync-ml-core.sh` в плагинах и, если менялись модель или словарь, `ml-models/go/README.md` с цифрами.
