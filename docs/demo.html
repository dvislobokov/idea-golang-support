Go в той IDE, которая у вас уже открыта

Пишите, рефакторьте, отлаживайте и тестируйте сервисы на Go там же, где живёт остальной код команды. Без второй IDE и без смены привычек.

Одна IDE на весь стек

Сервисы на Go рядом с Java, Python и фронтендом. Одни настройки, одни горячие клавиши, одно окно.

Свой анализ кода или gopls

Встроенный анализатор понимает Go сам: проверки потока данных, рефакторинги, иерархии. gopls остаётся на выбор одной настройкой, отладку выполняет Delve.

Код остаётся у вас

Подсказки работают на вашей машине. Исходный код не отправляется во внешние сервисы.

Редактор, который дописывает за вас

Меньше набора и меньше переключений внимания: редактор предлагает готовые строки и сам подключает пакеты.

  • Продолжение строки. Проверка ошибки и defer появляются серым текстом. Остаётся нажать Tab.
  • Импорт без усилий. Выберите функцию из списка, и нужный пакет подключится сам.
  • Исправления на месте. Alt+Enter обрабатывает ошибку вызова, добавляет недостающий return и создаёт функцию по её вызову.

Рефакторинги, которые понимают Go

Извлечь, встроить, перенести и удалить код без ручной правки вызовов. Изменение проверяется по потоку данных функции, поэтому смысл программы остаётся прежним.

  • Извлечение функции. Ctrl+Alt+M выносит строки в новую функцию. Параметры и результаты определяются сами, имя правится на месте.
  • Встраивание. Ctrl+Alt+N подставляет значение переменной, константы или короткой функции. Если подстановка изменит поведение, редактор скажет почему.
  • Перенос и удаление. F6 переносит объявление в другой файл или пакет вместе с импортами. Alt+Delete удаляет то, на что никто не ссылается, а у параметра убирает и аргументы в вызовах.

Сигнатура меняется во всех реализациях сразу

Параметр добавляется один раз. Интерфейс, его реализации, обёртки и моки получают его вместе, а вызовы переписываются под новый порядок аргументов.

  • Один диалог. Ctrl+F6: имя, параметры, их порядок и значение по умолчанию для новых.
  • Вся иерархия. Метод интерфейса меняется вместе с реализациями. Обёртка, которая делегирует вызов дальше, передаёт и новый параметр.
  • Конфликты заранее. Аргумент с побочным эффектом или функция, переданная как значение, показываются до того, как код изменится.

Ошибки видны, пока вы печатаете

Плагин строит граф потока данных каждой функции и проверяет его на ходу. Мьютекс без разблокировки или непроверенная ошибка подчёркиваются раньше, чем до них дойдут тесты.

  • Поток данных. Блокировка без разблокировки, недостижимый код, разыменование nil, ошибка, затёртая до проверки, потерянный контекст и незакрытый ответ HTTP.
  • Исправление рядом. Alt+Enter добавляет проверку ошибки и defer закрытия, убирает неиспользуемый параметр вместе с аргументами вызовов.
  • Проект и go.mod. Циклы импортов, чужие internal-пакеты, лишние и повторённые require, replace на несуществующий каталог.

Мелочи, которые экономят минуты

Встраивание одним нажатием, языки внутри строк и проверка кода под другую платформу.

Те же проверки в CI

Go | Inspect Project прогоняет проверки плагина по всему проекту и показывает находки в окне Inspection Results, с исправлениями. Go | Export Inspections to SARIF… пишет их в отчёт SARIF, а в CI то же самое делает сама IDE без окна: idea64.exe go-inspect. GitHub code scanning и GitLab показывают отчёт прямо в пулл-реквесте.

  • Как в редакторе. Профиль инспекций проекта, подавления //noinspection, файлы под текущие условия сборки. gopls не нужен.
  • Код выхода для пайплайна. 0 означает «чисто», 1 «есть замечания», 2 «запуск не удался».
  • Свой набор. --inspections выбирает проверки, --min-severity отсекает слабые.

Отладчик, к которому не нужно привыкать

Стандартное окно Debug со всеми его возможностями. Причина ошибки находится быстрее, когда состояние программы перед глазами.

  • Остановка там, где нужно. Условия, счётчики попаданий и остановка на панике.
  • Горутины на виду. Отдельная вкладка показывает, чем занята каждая горутина.
  • Любой сценарий. Программа, отдельный тест или уже работающий процесс.

Тесты, покрытие и бенчмарки в одном окне

Запуск, отладка и покрытие без командной строки. Результат каждого теста виден по ходу прогона.

  • Запуск от места в коде. Один тест, пакет или только упавшие.
  • Покрытие на виду. Процент по пакету и отметки у строк в редакторе.
  • Бенчмарки таблицей. Время и память на операцию по каждому бенчмарку.

Видно, как работает запущенная программа

Процессор, память и сборка мусора в окне IDE, пока программа выполняется. Без отдельных утилит и без остановки процесса.

  • Измерение, а не предположение. Данные снимаются с работающего процесса раз в секунду.
  • Память и сборка мусора. Размер кучи, паузы сборщика и его доля в нагрузке на процессор.

Зависимости под контролем

Модули проекта, их версии и вышедшие обновления в одном списке. Решение об обновлении принимается по фактам, а не по памяти.

  • Что устарело. Рядом с версией показана более новая, если она вышла.
  • Прямые и косвенные. Видно, что подключено вами, а что пришло вместе с другими модулями.
  • Команды под рукой. Tidy, Download и Vendor выполняются из меню, без терминала.

Всё остальное тоже на месте

Повседневные задачи решаются из IDE, без терминала и сторонних утилит.

Единый стиль кода

gofmt или goimports приводят файл в порядок при каждом сохранении.

Линтер в редакторе

Замечания golangci-lint рядом с кодом и исправления к ним по Alt+Enter.

Навигация

Использования и реализации над объявлениями, иерархии вызовов и типов, переход из ассемблера .s к функции Go.

Генерация кода

Конструктор, методы доступа, String(), тест, недостающие методы интерфейса и функция по её вызову.

Профили

Профиль процессора или памяти для тестов включается в конфигурации запуска.

Запуск без настройки

Для каждой программы проекта конфигурация запуска создаётся сама.

Сценарий демонстрации на 10 минут
  1. Открыть папку с go.mod. Конфигурации запуска созданы, сервер языка работает.
  2. Набрать код. f, err := os.Open(name), Enter, Tab; затем strings.ToUp и выбор из списка.
  3. Alt+Enter. Handle error на вызове, Create function по несуществующему вызову.
  4. Рефакторинги. Ctrl+Alt+M на строках цикла, Ctrl+Alt+N на переменной, Ctrl+F6 на методе интерфейса, F6 в другой пакет.
  5. Анализ. s.mu.Lock() и ранний return; GOOS/GOARCH в статус-баре на js/wasm.
  6. Отладка. Точка с условием в цикле, вкладка Goroutines, Evaluate с вызовом метода.
  7. Тесты. Окно Go Tests, Run with Coverage, Rerun Failed.
  8. Бенчмарк. Запуск из gutter, таблица результатов.
  9. Go Monitor. Запуск со сбором показателей рантайма, снимок горутин.
  10. Зависимости. Go, Modules, Dependencies: версии и обновления.
  11. Сохранение. Испортить форматирование, Ctrl+S; замечание линтера и исправление к нему.

Три шага до первой строки кода

  1. Проверьте инструменты

    Нужны Go, сервер языка gopls и отладчик Delve. Что найдено и каких версий, показано в Settings, Go — на страницах GOROOT и Tools.

  2. Откройте папку с проектом

    Достаточно каталога с go.mod. Сервер языка запустится сам, конфигурации запуска появятся в списке.

  3. Работайте

    Подсветка и шаблоны доступны сразу, подсказки и навигация включаются после загрузки пакетов. Состояние сервера видно в статус-баре.
