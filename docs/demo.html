Редактор, который понимает код

Смысл кода даёт gopls, тот же сервер, что стоит за Go в VS Code. Подсветка, структура и шаблоны работают и без него.

  • Серый текст по Tab. if err != nil с return под сигнатуру функции, defer для файла, мьютекса и контекста, if !ok. Правила, а не модель.
  • Alt+Enter. Исправления gopls и staticcheck, Handle error, Create function из вызова, Extract и Inline.
  • Навигация. Объявление, реализации интерфейса, usages, тип выражения, счётчики над объявлениями.
  • Completion с автоимпортом. Выбрали ToUpper, и import "strings" появился сам.

Отладчик на delve в обычном окне Debug

Собственный клиент протокола отладки. Он не зависит от модулей платформы, поэтому работает и в форках.

  • Точки останова. Условие, счётчик попаданий, сообщение в лог, остановка на панике.
  • Данные. Переменные, Watches, Evaluate с вызовом функций, Set Value, []byte и ошибки читаемым текстом.
  • Горутины. Отдельная вкладка с группировкой по функции, поиском и фильтром системных.
  • Подключение. Attach к процессу, готовый бинарник, core dump, удалённый dlv dap.

Тесты, покрытие и бенчмарки

Дерево растёт, пока идёт go test. Отдельное окно Go Tests помнит, чем закончился прошлый прогон.

  • Запуск. Кнопка у Test, Benchmark, Fuzz, Example, у t.Run и у строки табличного теста.
  • Покрытие. Полосы в редакторе и процент у пакета после Run with Coverage.
  • Бенчмарки. Таблица ns/op, B/op и allocs/op с разницей против прошлого прогона.
  • Цикл. Rerun Failed и перезапуск тестов пакета при сохранении.

Модуль, а не папка с файлами

Зависимости видны в дереве проекта вместе с исходниками. Команда go остаётся источником правды.

  • go.mod и go.work. Подсветка, сворачивание блоков, completion путей модулей и версий.
  • Dependencies. Прямые и косвенные зависимости, замены, исходники из module cache.
  • Обновления. Окно Go Dependencies: новые версии, Upgrade, Tidy, проверка govulncheck.
  • Сборка. Build, Vet и Generate с деревом ошибок, подсказка tidy после правки require.

И всё, что нужно вокруг кода

Плагин не пишет свой анализатор Go. Он подключает инструменты, которыми сообщество уже пользуется, и даёт им интерфейс IDE.

Go Monitor

Графики CPU, памяти, кучи, пауз GC и планировщика. В списке есть любая Go-программа машины, а не только запущенная из IDE.

Линтер

golangci-lint первой и второй версии с конфигурацией репозитория. Исправления для errcheck и //nolint из Alt+Enter.

Форматирование

gofmt, goimports или golangci-lint fmt по Ctrl+Alt+L и при сохранении.

Настройки gopls

Страница строится по каталогу установленной версии сервера. Рядом окно с его логом и перезапуск одной кнопкой.

Профили

CPU, память, блокировки, мьютексы и трасса выполнения тестов. Результат открывается в pprof.

Шаблоны

41 live template, 25 postfix-шаблонов, Generate по Alt+Insert: конструктор, аксессоры, теги структур, методы интерфейса, тест.

Чего в плагине нет
  • Change Signature, Move, Safe Delete, Extract Interface. Для них нужен свой парсер Go.
  • Flame graph и профилирование приложения. Профили снимаются только с тестов и смотрятся в pprof.
  • Endpoints, Go templates, cgo и ассемблер. У шаблонов есть только значок файла.
  • Точки останова на функцию, watchpoints, Smart Step Into, обратная отладка.
  • Type и Call Hierarchy, загрузка Go SDK из IDE, запуск в Docker, WSL и по SSH.
Сценарий демо на 10 минут
  1. Открыть playground. Structure с методами под типом, узел Dependencies, окно Go on This Machine.
  2. Набрать код. f, err := os.Open(name) и Tab, затем strings.ToUp с автоимпортом и items.for.
  3. Alt+Enter. Handle error, Create function, Refactorings and actions of gopls, затем Shift+F6.
  4. Навигация. Ctrl+B на NewOrder, значок реализаций у Priced, счётчики usages.
  5. Запуск. cmd/shop из gutter, графики в Go Monitor.
  6. Отладка. Точка в Total, Evaluate order.Total(), вкладка Goroutines.
  7. Тесты с покрытием. Go Tests, Run with Coverage, кейс TestTotal/empty, Rerun Failed.
  8. Бенчмарк. BenchmarkTotal два раза, разница во вкладке Benchmarks.
  9. Модули. Completion версии в go.mod, баннер tidy, окно Go Dependencies.

С чего начать

  1. Поставьте Go и инструменты

    Нужен сам go. Недостающие gopls, dlv, goimports и golangci-lint плагин предложит поставить при открытии проекта. Пути задаются в Settings, Tools, Go.

  2. Откройте папку с go.mod

    Подойдёт и каталог с go.work. Для каталогов с func main конфигурации запуска появятся сами.

  3. Дождитесь gopls

    Сервер виден в виджете Language Services внизу окна. До этого уже работают подсветка, структура и серый текст.

Клавиши и приёмы собраны в меню Go, пункт Help Page. Логи отладчика открывает Go, Debugger, Show Debugger Logs. В GoLand и рядом с плагином Go от JetBrains плагин не ставится: там поддержка Go уже есть.
