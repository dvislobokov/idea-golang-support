# Completion: плагин, gopls и GoLand (prometheus, 2026-10-13)

Часть 2 сравнения. Проект и условия — как в части 1 (`prometheus-broken-2026-10-13.md`): prometheus v3.15.0, Go 1.27.1, windows/amd64.
Эталон — GoLand 2026.2.3 на копии клона (`build/compare/prometheus-goland`, робот на 8595). Второй ориентир — gopls v0.23.0
(`textDocument/completion`, порядок по `sortText`, как его получает VS Code до своей фильтрации).

**Как сняты цифры плагина.** Плагин мерился стендом (`GoCompletionHarnessTest`: light-проект с клоном как content root, completion
`myFixture.complete`, live- и postfix-шаблоны включены, как в IDE). GoLand — живой IDE через робота. Сценарии в разделе 2: GoLand —
робот, плагин — стенд, шаги одинаковые. **Повтор в живой IDEA с плагином** — те же JS-драйверы, что для GoLand, на песочнице
(`TARGET=plugin`, порт 8083, раздел «Как повторить»); он ещё не сделан. Латентность стенда не равна латентности живого редактора: в нём
нет автопопапа и отрисовки списка.

## 1. Массовый замер «восстанови удалённое»

17 файлов из 13 пакетов, 420 мест: по 60 на каждый из 7 видов, не больше 6 мест на один идентификатор. Места выбраны по go/types:
`tools/compare/sites`, `docs/compare/prometheus-completion-dumps/sites.json`. Хвост идентификатора стирается до префикса 0, 1 и 3 символа
(если имя длиннее). Для пакета без импорта стирается и строка импорта. Всего 1136 попыток, у всех трёх сторон одни и те же.
Попаданием считается пункт, равный идентификатору. Для пакета без импорта попаданием считается и его путь, и пункт вида `pkg.Name`:
GoLand предлагает не имя пакета, а член пакета, и импорт приходит с ним.

**Как читать GoLand.** У GoLand ниже top-1 по двум причинам. Первая: на пустом префиксе он ставит наверх ключевые слова и пакеты
(`config`, `discovery`), а не локальные имена. Вторая: пакет без импорта он даёт членами (`math.Abs`), а не именем. Это не «GoLand хуже»:
мера — «первый пункт равен стёртому имени», а GoLand ранжирует под другой сценарий (ML-ранжирование по истории набора). Ориентир для
плагина по ранжированию — gopls. GoLand — эталон того, *что* должно быть в списке и что вставляется (раздел 2).

### Что стоит выше правильного ответа у плагина

Плагин не на первом месте в 617 попытках. В 143 из них gopls или GoLand ставят правильный ответ первым — это и есть наш разрыв.
Разбор пунктов над правильным ответом: `prometheus-completion-dumps/causes.md`, `plugin-misses.json`.

| Причина | Пример (вид / префикс: имя → что выше) | + top-1, оценка |
|---|---|---|
| Ключевые слова и встроенные там, где они не к месту: в ключе литерала, в `case`, после точки | `T{s` → `make, select, switch, switch` над `serverURL`; `T{E` → `if` над `EnableAtModifier` | +1,3 п.п. |
| Длинное имя с тем же началом выше точного (`KeepEqual` над `Keep`, `DropEqual` над `Drop`, `PositionRange` над `PosRange`, `errors` над `error`) | case / 3: `Kee` → `KeepEqual, Keep` | +1,6 п.п. |
| Пункт, равный набранному префиксу, и обрывки слов (`tar`, `mer`, `qu`, `lint`, `ta`, `se`) — слова из текста, а не символы | statement-start / 3: `tar` → `tar, target` | +1,0 + 1,2 п.п. |
| В позиции типа пакет или `struct` выше типа (`errors` над `error`, `struct, strings` над `string`, `bytes` над `byte`) | type / 3: `str` → `struct, strings, string` | +0,5 п.п. |
| Тип выражения switch не поднимает свои константы (case по константам: 26,6 % против 46,8 % у gopls) | case / 0: `lintOptionAll` → `option, optionsStr, …` | ~+2,2 п.п. (разница с gopls на 124 попытках) |
| Начало оператора с префиксом 1: локальные переменные ниже `if`, `go`, `make` и пакетов | statement-start / 1: `g` → `g, go, group` | ~+1,1 п.п. |
| Тип в составном литерале (`T{`) | type / 0: `Sample` — 16-е место | ~+0,8 п.п. |

Первые четыре строки поддаются механической правке. По пересчёту на тех же данных их сумма даёт **+4,6 п.п. top-1** (45,7 → ~50,3 %),
две последние — ещё ~+3 п.п.

Кроме ранжирования:
- **Дубликаты в списке**: в 140 попытках из 1136 в первой пятёрке есть два одинаковых пункта (`if, if, if`, `chan, chan`, `switch, switch`,
  `annotations` трижды). На top-1 это почти не влияет, но список выглядит сломанным.
- **Пакет без импорта.** Чего нет в списке, — только на префиксе 0. Там пакетов нет ни у кого: 100 % у плагина и GoLand, 97 % у gopls.
  Плагин выбирает пакет и сам добавляет импорт. Пакет выбирался в 60 случаях: в 46 импорт добавлен ровно тот, что был в файле. В 14 —
  другой пакет с тем же именем или локальная переменная с тем же именем (`regexp` вместо `github.com/grafana/regexp`, `yaml`, `config`,
  `model`, `trace`, `labels`). Подробно — `insertions` в `completion-*.json`.
- **Латентность.** Медиана у плагина ниже всех, p95 255 мс. Максимум 6,6 с — первый вызов после индексации (прогрев). У gopls p95 1,4 с —
  первые запросы к пакету.

## Что чинить

Оценка «+top-1» — пересчёт массового замера: пункты, которые правка убирает или опускает, вычеркнуты из списков.

1. ✅ **Сделано в 0.2.231** (проверено в IDE: `rand.Int` — math/rand первым, все пакеты с путями). **Одноимённые пакеты: молча выбирается один** (C09, C10; 14 из 60 вставок в массовом замере). Надо показывать все варианты с путём
   и не вставлять автоматически, когда кандидатов больше одного. На top-1 не влияет, но вставляет **не тот** импорт: код собирается и
   делает другое (`crypto/rand.Int` против `math/rand.Int`), либо не собирается. Чинить первым среди completion.
2. ✅ **Сделано в 0.2.232** (проверено в IDE). **Шаблон `.rr` разворачивался в `return err, nil`** (C19), а в GoLand это `if err != nil { return err }`. Привести к GoLand;
   `return expr, nil` оставить под другим ключом, если нужен.
3. **Ключевые слова и встроенные не к месту** (ключ литерала, `case`, после точки) и **дубликаты** пунктов: **+1,3 п.п.** top-1, плюс
   чистый список в 140 попытках из 1136.
4. **Точное совпадение и короткое имя выше длинного с тем же началом** (`Keep` над `KeepEqual`, `error` над `errors`, `string` над
   `strings` / `struct` в позиции типа): **+2,1 п.п.**
5. **Пункты-обрывки** (пункт, равный набранному префиксу, слова `tar`, `qu`, `mer`): **+2,2 п.п.** Источник — словарные пункты по
   тексту файла. Не показывать их, когда есть символ с тем же началом.
6. **Ожидаемый тип в `case`**: поднимать константы типа выражения switch. Case-константы сейчас 26,6 %, у gopls 46,8 % — **~+2,2 п.п.**
   **Начало оператора с префиксом 1** — локальные выше ключевых слов: **~+1,1 п.п.**
7. **Заготовки «missing method of …» на верхнем уровне** (C23, C25: 50+ пунктов перед `func`) — шум. Предлагать их только для типов,
   которые где-то используются как этот интерфейс, или убрать из обычного списка (GoLand показывает их в Alt+Insert).
8. **Tab на методе без аргументов ставит каретку внутрь `()`** (C05/C06). У Enter каретка после `)`, как и у GoLand.
9. `.var` без шаблона имени (C20) и `.for` (C17) — поведение отличается от GoLand, но рабочее. Если делать как в GoLand: `.var` с
   редактируемым именем.

Сумма пп. 3–6 — около **+7 п.п. top-1** (45,7 → ~53 %), выше gopls. Перед правкой ранжирования в корпус (`testData/`) лечь не обязано:
правила проекта требуют регрессионного теста на правку. Пример для каждого пункта — строка из `plugin-misses.json` (место, префикс,
что выше).

