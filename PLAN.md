# План улучшения DX

Составлен 2026-09-21. Что уже сделано и проверено — в `ROADMAP.md`; здесь — что делать дальше и в каком порядке, от того, что раздражает каждый
день, к тому, что просто приятно иметь. Оценки «дёшево / средне / дорого» — про объём работы. Сделанный пункт отмечать здесь и переносить в `ROADMAP.md`.

## Порядок

1. **Блок 1 целиком** (отступы, format-on-save, шаблоны файлов, автоконфигурации) — этого не хватает при любом использовании.
2. **Замер LSP-трафика под кэширование** (полдня, см. ниже) — покажет, есть ли там вообще что ускорять.
3. **Статус gopls и умная установка инструментов** — без них любой сбой выглядит как «плагин не работает».
4. **Покрытие и запуск кейса table-driven теста.**
5. **Монитор и pprof** — большая фича, сравнимая с .NET Monitor.

Остальное — по мере надобности.

## 1а. Навигация, которой нет в LSP-клиенте платформы (добавлено и сделано 2026-09-21)

Платформенный клиент (2026.1) не показывает ссылку под Ctrl + мышь, не знает `textDocument/implementation`, не считает usages, а Find Usages с объявления,
которое является нашим PSI-элементом, не запускает вовсе. Закрыто в модуле `lsp` запросами к тому же gopls (`GoplsNavigation.kt`, `GoplsCodeVision.kt`):

- [x] «N usages» / «N implementations» над объявлениями (code vision; считаются в фоне раз на изменение файла) — робот
- [x] Find Usages / Show Usages с объявления (`customUsageSearcher` + `GoFindUsagesProvider`) — робот, через API
- [x] Go to Implementation с объявления интерфейса, метода, типа (`definitionsScopedSearch`) — робот, через API
- [x] Go to Declaration через PSI-цели (`GotoDeclarationHandler`; у платформы go-to-definition выключен, иначе цели двоятся) — робот, через API
- [ ] **Проверить вживую подсветку ссылки при Ctrl + наведении**: робот мышью не водит. Механизм тот, которым платформа пользуется для PSI-целей
- [ ] Go to Implementation / Find Usages **с места использования**, а не с объявления: цель там определяет платформа, у неё наш токен ни на что не ссылается
- [x] Gutter-иконки «is implemented» (интерфейс и его методы) и «implements» (тип и его методы) с переходом — `GoplsImplementationLineMarkerProvider`; иконки — робот, клик не проверен

## 1б. Действия по Alt+Enter (добавлено 2026-09-21; уровни A и B сделаны)

Откуда у нас берутся действия: исправления при предупреждениях, code actions gopls, свои intentions. У GoLand за этим свой разбор кода и сотни инспекций.

- [x] **A. Всё, что умеет gopls.** staticcheck включён по умолчанию; линзы `go.mod` и `//go:generate` заданы явно, плюс vulncheck; пункт
  «Refactorings and actions of gopls...» — попап со всем, что сервер предлагает для каретки или выделения (Extract variable / function, Inline call,
  Fill struct, Add test…). Нужен, потому что клиент платформы в месте без диагностики сервера ничего не показывает, хотя gopls на прямой вопрос
  отдаёт 7 действий (`tools/gopls/probe.py`). Попап вживую не проверен: робот видел пункт в списке, но не открывал его.
- [x] **B. Исправления к находкам golangci-lint.** errcheck: «Handle error» и «Ignore error explicitly» (число результатов — из hover gopls, через
  точку расширения `signatureProvider`); любое правило: «Suppress with //nolint:правило». Робот: в месте со скриншота 4 действия, «Handle error» даёт
  `_, err := os.Open("x")` с проверкой.
- [ ] Автоисправления из отчёта линтера (`SuggestedFixes`): найти правило, которое их отдаёт, и посмотреть форму.
- [ ] Предупреждения линтера исчезают после любой правки и до сохранения (линтер читает диск). Держать старые со сдвигом по строкам или запускать по сохранению в фоне чаще.
- [x] **Идиомы серым текстом, Tab — принять** (`GoIdioms` + `GoInlineIdiomsProvider`, inline completion платформы, правила без ИИ): после присваивания
  ошибки — `if err != nil { return <нулевые значения под сигнатуру>, err }` (в `main` — `log.Fatal`, в тесте — `t.Fatal`, именованные результаты — по именам);
  `defer cancel()` после `context.With*`, `defer mu.Unlock()` после `Lock()`, `defer ticker.Stop()`; после проверки ошибки открытия — `defer f.Close()`,
  `resp.Body.Close()`, `rows.Close()`, `tx.Rollback()`. Робот: `if err != nil` показан и принят; цепочка с `defer` — только юнит-тест.
  Кандидаты в правила: `if !ok` после comma-ok, `defer wg.Done()` в горутине, `defer close(ch)`, `errors.Is/As`, `for rows.Next()` после `Query`.
- [ ] **C. Свои intentions на ответах gopls**: «Handle error» на любом вызове с `error` (без линтера), конструктор и getter/setter по структуре,
  Implement interface, Iterate over; постфиксные шаблоны `.err`, `.nn`, `.var`, `.for`, `.if`, `.return` (по токенам, парсер не нужен).
- [ ] **D. Свой парсер и PSI Go** (недели): локальные инспекции, surround / unwrap, Find Usages и Go to Implementation с места использования. Кандидат на
  основу — грамматика заброшенного go-lang-idea-plugin (Apache 2.0; лицензию и состояние проверить, generics и модулей там нет). Отдельное решение.

## Кэширование ответов gopls

Сделать можно, но кэшировать сами completion смысла нет: ответ LSP привязан к версии документа и позиции, любое нажатие клавиши меняет версию, и кэш
попадал бы только при повторном вызове в том же месте. gopls и так держит у себя типы и пакеты — это основная стоимость запроса.

Что реально можно ускорить на стороне плагина:
- [ ] **Документация к пунктам списка** (`completionItem/resolve`): дока символа меняется редко, ключ «символ + пакет». Самый заметный эффект при листании списка.
- [ ] **Hover** по ключу «файл + версия + позиция»: повторное наведение и быстрая дока без обращения к серверу.
- [ ] **Completion с `isIncomplete=false`**: клиент фильтрует первый ответ локально, без новых запросов. Сначала посмотреть, что gopls отдаёт сейчас.
- [ ] Настройки самого gopls: `completionBudget`, отключение ненужных анализаторов.

Запросы шлёт платформа, а не плагин, поэтому кэш придётся встраивать прокси-слоем вокруг процесса gopls — тем же приёмом с потоками, что в отладчике
(`DapMessageRewritingStream` / `DapMessageWatchingStream`).

- [ ] **Сначала замер:** включить трассу LSP и посмотреть, какие запросы медленные и как часто повторяются, чтобы не кэшировать то, что и так отвечает за миллисекунды.
